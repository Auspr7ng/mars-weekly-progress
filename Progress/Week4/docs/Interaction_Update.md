# Body-relative joystick and camera controls

The `body_follow_v3` interface uses a turquoise ball above the head. Grab the ball directly and drag diagonally to combine forward/back speed and steering. The red arrow marks the current body-forward direction. The base position follows the head and the axes follow current base-link yaw on every display update, including during a held gesture.

Deflection is stored in body coordinates. A stationary pointer retains the same throttle/steering deflection while the robot turns. New mouse movement is converted using the current rendered camera quaternion, perspective at the current handle position and current body yaw. The horizontal-plane intersection uses the ray through the handle, so a robot away from screen centre retains the same visible forward direction. Only incremental pointer motion changes the deflection: robot movement and camera following do not manufacture mouse input. The base and input orientation are never frozen at grab time. Release, Stop and client disconnect clear the vector and velocity request. Projection gain is bounded at low viewpoints.

The camera starts with **Follow robot position off**. Empty-space dragging orbits, right-dragging pans, and the wheel zooms. Keyboard camera translation is also available. **Reset camera view** restores the robot view. Optional following refreshes offsets from client camera updates and stays active while the joystick is held, preserving the selected view as the robot moves.

The regression in `code/scripts/check_body_joystick.py` uses real MuJoCo poses and the actual drag callback at 0, +90, 180 and -90 degrees. It checks translated head tracking while held, rotated visual axes, new forward mouse input after each turn, unchanged body commands when only the robot/camera moves, steering, release and disconnect. Evidence is `results/validation/body_follow_v3_contract.json`; live browser evidence and the current screenshot are linked by `results/validation/body_follow_v3_result.json`. Earlier `free_drag_v2` browser evidence remains archived and is superseded for held tracking and heading behavior.

This updates the interaction layer. The 1200-command simulation acceptance and gait measurements in [Acceptance report](Acceptance_Report.md) remain those of the frozen R25-300 policy. Hand and foot distance heatmap implementation is unchanged.
